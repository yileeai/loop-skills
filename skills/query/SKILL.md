# query：从知识库里找答案

## 流程

### 1. 查目录（永远的第一步）
读取 `20-Wiki 知识/知识总目录.md`，定位相关的概念方法、AI 工具、行业、问题、观点、案例、素材摘要、综合研究。

如果问题涉及具体客户（"王总那边进展如何"），再查 `30-Action 行动/客户档案/` 和 `40-Review 复盘/咨询记录/`。

### 2. 深读
打开最相关的 3–8 个页面完整阅读。必要时顺着 `## 关联连接` 再读一层。

### 3. 综合回答
- 结论先行，再给依据和可执行建议。
- 引用规范：引用某页内容时标注 `[[页面名]]`；同一页面在一段里只标一次；原文引用用 `>` 块引用。
- 库内找不到依据的部分，单独成段并注明：`本地知识库中未找到，以下为通用知识：`。
- 发现库里的知识互相矛盾时，指出来，并建议主人决定以哪个为准。

### 4. 沉淀高价值回答
如果回答超过两段、或带有对比分析 / 方法总结，询问主人：
> 这个总结有价值，要保存到 `20-Wiki 知识/主题地图/综合研究/` 吗？

主人同意后创建 `研究-<slug>.md`：

```markdown
---
up:
  - "[[知识总目录]]"
related:
created: YYYY-MM-DD
type: synthesis
tags: [综合研究]
sources: []
last_updated: YYYY-MM-DD
---

# （问题）

（回答正文，保留双链）

## 关联连接
- [[…]]
```

并在 `知识总目录.md` 的「综合研究」分类登记。

### 5. 记日志
无论是否保存，都在 `20-Wiki 知识/编译日志.md` 末尾追加：
```
## [YYYY-MM-DD] query | 问题简述
- **输出**: 引用 [[…]], [[…]]；（已保存为 [[研究-…]] / 即时回答未保存）
```

## 发现知识缺口时
如果问题很常见但库里没有，建议主人：找什么类型的素材放进 `10-Raw 原料/`，然后运行 `/ingest`。
