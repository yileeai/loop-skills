# ingest：素材 → 知识

先读 `CLAUDE.md`、`20-Wiki 知识/知识总目录.md` 和 `20-Wiki 知识/主题地图/知识蓝图.md`。

## 蓝图相关性检查（每份素材先做）
快速浏览素材，判断它服务蓝图的哪一块（一、诊断 / 二、生意判断 / 三、获客 / 四、底座）或矩阵哪一格。
- 明确相关 → 正常编译，摘要里写明对应哪一块 / 哪一格。
- 只属于「四、底座」→ 正常编译，但只提炼与主攻行业或咨询有关的部分，不铺满细节。
- 与蓝图无关 → **先暂停，告诉主人**「这份素材跟蓝图关系不大」，由主人决定编译、精简编译还是跳过。

## 待编译范围

- `10-Raw 原料/05-我的逐字稿/`、`10-Raw 原料/06-AI对话/`：主人自己的内容，走下方「主人原稿」流程

## 主人原稿（05-我的逐字稿 / 06-AI对话）
这两类是主人自己的话，价值在**观点和决策**，不是信息量。流程与外部素材不同：
1. 通读，列候选（格式同 `/loopback` 第 1 步），**不直接写入**：
   - **观点**：主人说出的判断，保留原话，标出时间点或段落
   - **决策**（仅 AI 对话）：做了什么选择、为什么
   - **问题**：观众 / 学员 / 主人自己提出的老板会问的问题
   - **公开建造故事**：这段过程能讲成什么内容，适合哪个平台
   - **切片候选**（仅逐字稿）：可单独切成短视频 / 笔记的片段
2. 主人勾选后写入：观点 → `知识节点/观点/`；问题 → `知识节点/问题/`；故事 → 追加到 `30-Action 行动/工作成果/内容作品/公开建造选题.md`「待写」；切片候选 → 告诉主人可用 `/content 从逐字稿切片`。
3. 照常写素材摘要（`type: source`，`tags` 加 `主人原稿`）、登记、写日志、归档。
4. **隐私**：AI 对话或授课里提到客户的，按客户隐私红线脱敏后再进知识地图。

## 每份素材的流水线（外部素材 01–03）

### 1. 读取
- `.md` / `.txt`：完整读取。
- `.pdf`：尝试提取文本；提取失败就只记录文件名、页数，并在摘要里注明"需人工补充"。
- 非中文内容：翻译成中文。

### 2. 提炼
从素材中提取：
- **核心主旨**（1–2 句）
- **概念方法**：框架、方法论、模型
- **AI 工具**：模型、软件、平台、产品
- **人物机构**：人物、公司、组织
- **行业**：素材涉及的行业及其 AI 落地场景
- **问题**：素材能回答的"老板会问的问题"
- **案例**：有具体数据的落地案例（脱敏）
- **获客内容线索**：哪些信息是目标客户（老板）不知道、但听了会心动的「信息差」

### 3. 写素材摘要
在 `20-Wiki 知识/信息来源/素材摘要/摘要-<slug>.md` 创建：

```markdown
---
up:
  - "[[知识总目录]]"
related:
created: YYYY-MM-DD
type: source
tags: [素材摘要]
sources: [10-Raw 原料/09-已归档/<原文件名>]
last_updated: YYYY-MM-DD
---

## 核心摘要
（3–5 句）

## 关键要点
- …

## 咨询中怎么用
（这份资料能帮哪类客户解决什么问题）

## 获客内容线索
- 信息差 1：…（适合做成什么选题）

## 关联连接
- [[概念或工具页]] — 关系说明
```

> `sources` 直接写归档后的路径（第 6 步会移动过去）。

### 4. 知识网络化
对第 2 步提取的每个实体 / 概念 / 行业 / 问题 / 案例：

| 类型 | 目录 |
|---|---|
| 概念方法 | `20-Wiki 知识/知识节点/概念方法/` |
| AI 工具 | `20-Wiki 知识/知识节点/AI工具/` |
| 人物机构 | `20-Wiki 知识/知识节点/人物机构/` |
| 行业 | `20-Wiki 知识/知识节点/行业/` |
| 问题 | `20-Wiki 知识/知识节点/问题/` |
| 案例 | `20-Wiki 知识/知识节点/案例/` |
| 打法 | `20-Wiki 知识/知识节点/打法/`（仅当素材有某行业某环节的具体做法时） |

- 页面不存在 → 按 `CLAUDE.md` 的 frontmatter 规范新建，正文结构：`## 定义` / `## 关键信息` / `## 咨询中怎么用` / `## 关联连接`。`up` 指向对应的主题地图（[[AI咨询方法论]]、[[AI工具地图]]、[[行业地图]]、[[问题库]]、[[案例库]]）。
- 页面已存在 → 读取后**增量合并**，更新 `last_updated`，在 `sources` 追加新来源。
- 发现与旧知识冲突 → **暂停**，向主人报告冲突点，给出选项：A) 两者都保留并标注 `## 知识冲突`；B) 新覆盖旧；C) 放弃本次。按主人选择继续。

### 5. 更新登记
- `20-Wiki 知识/知识总目录.md`：把每个新页面加入对应分类，格式 `- [[页面名]] — 一句话描述`。
- `20-Wiki 知识/编译日志.md`：末尾追加
  ```
  ## [YYYY-MM-DD] ingest | 简述
  - **变更**: 新增 [[…]]; 更新 [[…]]
  - **冲突**: 无
  ```

### 6. 归档
以上全部完成后，把源文件**原样移动**到 `10-Raw 原料/09-已归档/`（同名冲突时在文件名后加 `-2`）。绝不修改源文件内容。

用 3 行告诉主人：编译了几份素材、新建 / 更新了哪些页面（对应蓝图哪一块）、发现了哪些值得做内容的信息差。
