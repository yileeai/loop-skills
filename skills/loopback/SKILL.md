# loopback：成果 → 知识

输出也是原料。一份成果**定稿就回流**，不攒批。

先读 `CLAUDE.md`、`20-Wiki 知识/知识总目录.md`、`20-Wiki 知识/主题地图/知识蓝图.md`。

## 输入
- `/loopback <文件路径或[[文件名]]>`：通常在 `30-Action 行动/工作成果/`（内容作品 / 咨询交付 / 产品SOP）。
- `/loopback`（不带参数）：列出 `30-Action 行动/工作成果/` 下 `WIPstatus` 不是 `active`、且没有 `harvested` 字段的成果，问主人先回流哪份。
- 文件 `WIPstatus` 仍是 `active` 时，先问主人：是否已定稿？定稿就把 `WIPstatus` 改为 `simmering`（或主人指定的值）再继续。
- 文件已有 `harvested` 字段：说明回流过，只处理上次之后新增的部分，并告诉主人。

## 第 1 步：读成果，列候选（不写任何知识页）

通读成果，按五类找可复用的东西。**只找跨项目、跨客户还能用的**，项目专属细节（具体排期、某个虚构示例公司）不收。

| 类型 | 收什么 | 去向 |
|---|---|---|
| 观点 | 成果里体现的**主人的判断**：定位、取舍、"不做什么" | `知识节点/观点/` |
| 打法 | 某行业在某业务环节怎么用 AI（对应蓝图矩阵一格） | `知识节点/打法/打法-<行业>-<环节>.md` |
| 概念方法 | 可迁移的方法、框架、结构（如交付组合、课程结构） | `知识节点/概念方法/` |
| 问题 | 成果在回答的、老板会问的问题 | `知识节点/问题/` |
| 案例 | **有真实结果数据**的才算，必须脱敏 | `知识节点/案例/` |

另外检查：涉及的行业 / AI 工具是否已有页面，没有的列为「新建行业页 / 工具页」候选；已有的列为「更新」候选。

按下面格式给主人看，然后**停下等主人勾选**：

```markdown
## 🌾 回流候选 — [[成果文件名]]

### 观点（请勾选，可以直接改成你的话）
- [ ] 1. 「……」 — 出处：第 X 节「……」 → 蓝图：二、生意判断
### 打法
- [ ] 2. 打法-教育培训-提效：…… — 出处：…… → 矩阵：教育培训 × 内部提效
### 概念方法
- [ ] 3. ……（新建 / 合并进 [[已有页]]）
### 问题
- [ ] 4. ……（新建 / 已有 [[问题页]] asked_count +1）
### 案例
（无：成果中没有真实结果数据）
### 公开建造故事
- [ ] 6. 这份成果的制作过程能讲成什么内容 → 追加到 [[公开建造选题]]
### 行业 / 工具页
- [ ] 5. 更新 [[行业页]]：补充……

回复编号即可，例如"1 2 4，观点 1 改成：……"。
```

## 第 2 步：按勾选写入
- 只写主人勾选的条目。观点**用主人确认或改写后的原话**，不润色立场。
- 新页面按 `CLAUDE.md` 规范：frontmatter 完整，正文 `## 定义` / `## 关键信息` / `## 咨询中怎么用` / `## 关联连接`；`up` 指向对应地图（[[观点库]]、[[知识蓝图]]、[[AI咨询方法论]]、[[问题库]]、[[案例库]]、[[行业地图]]）。
- 已有页面 → 增量合并，更新 `last_updated`，`sources` 追加成果路径。
- 每个写入页的 `sources` 都写成果的相对路径（如 `30-Action 行动/工作成果/产品SOP/xxx.md`），并在 `## 关联连接` 里链回成果：`- [[成果文件名]] — 出处`。
- 打法页：`industry`、`step` 填好；成果是真实交付给客户的，`verified_count` +1（新页从 1 开始），达到 3 时提醒主人提炼 SOP。只是设计稿、未交付的，`verified_count: 0`。
- 新行业 / 新环节不在蓝图矩阵里 → 先问主人，不自行加行。
- **隐私**：知识地图里不得出现真实客户名、公司名；用「行业 + 规模 + 城市级别」描述。成果里的虚构示例公司名也不要带进知识页。
- 公开建造故事 → 追加到 `30-Action 行动/工作成果/内容作品/公开建造选题.md`「待写」，格式 `- [ ] YYYY-MM-DD 故事一句话 — 出处 [[成果]] — 适合平台`。
- 内容作品回流时，有 `views` / `leads` 数据的，在用到的观点页和问题页里记一笔效果（哪个平台、多少数据）。
- 与已有知识冲突 → 不覆盖，建 `## 知识冲突` 区块并告诉主人。

## 第 3 步：回写成果（只追加，不改正文）
- frontmatter 增加或更新 `harvested: YYYY-MM-DD`。
- 文件末尾追加（已有则在区块内追加）：
  ```markdown
  ## 已沉淀
  - YYYY-MM-DD → [[观点页]] · [[打法页]] · [[概念页]]
  ```

## 第 4 步：登记与日志
- `20-Wiki 知识/知识总目录.md`：新页面登记到对应分类。
- `20-Wiki 知识/编译日志.md` 末尾追加：
  ```
  ## [YYYY-MM-DD] loopback | <成果文件名>
  - **变更**: 新增 [[…]]; 更新 [[…]]; 回写 [[成果文件名]]
  - **冲突**: 无
  ```

## 收尾
3 行告诉主人：沉淀了几条（观点 / 打法 / 方法 / 问题各几条）、填进了蓝图哪几格、哪条最适合拿去做获客内容。
