# content：知识 → 获客内容

## 先读主人的方法和品牌
1. `20-Wiki 知识/知识节点/概念方法/获客内容结构.md`
2. `20-Wiki 知识/知识节点/概念方法/AI信息差画面.md`
3. `90-System 系统/LOOP品牌手册.md`：语气、固定口播（开场 / 结尾 / 行动一字不改）、标题公式四选一、写法规则（LOOP 全大写、工具名用官方写法、阿拉伯数字）、封面规则（一张封面只说一件事、只有一个强调色词）

4. **目标平台的账号档案** `30-Action 行动/媒体账号/<平台>.md`：定位、受众、调性、引流路径。按档案写，不同平台不是同一稿换格式。

如果前两页还是空模板（只有引导问题），告诉主人"你的方法还没写进库，这次先用默认结构"，并使用默认结构：
**钩子（反常识 / 信息差）→ 痛点共鸣 → 拆解方法（3 步以内）→ 证据（案例 / 数据）→ 行动指令（私信关键词 / 领资料）**

## 选题
- `/content <主题>`：围绕主题，在 `知识总目录.md` 里找相关的问题、观点、案例、素材摘要。
- `/content 从逐字稿切片 <逐字稿或[[长视频]]>`：从主人的长视频 / 直播逐字稿里找 3–5 个最反常识、最能独立成立的片段，切成小红书 / 抖音版本（保留主人原话，标注出处时间点）。
- `/content 从建造选题`：读 `30-Action 行动/工作成果/内容作品/公开建造选题.md` 的「待写」，写完把该条移到「已写」并链到作品。
- `/content 从问题库选`：读取 `20-Wiki 知识/知识节点/问题/`，优先选 `asked_count` 高、`used_in` 为空的问题，给主人 5 个选题，每个附一句"为什么老板会点进来"，等主人选。

## 写作
每个选题输出：
1. **3 个标题**（不同钩子角度）
2. **正文**，按平台：
   - 小红书：300–600 字，分段短句，结尾行动指令
   - 视频号 / 抖音口播：60–90 秒口播稿，标注【画面】提示
   - 公众号：1500 字左右，小标题结构
3. **AI 信息差画面**：2–3 条可直接丢给即梦 / 豆包 / Midjourney 的画面提示词（中文），画面要让外行一眼看出"AI 能做到这个"。画面配色按品牌：根据地黑 `#0F0E0C` 为底，松绿 `#3CC48E` 只给一个词或一个数字，不用蓝紫渐变
4. **引流钩子**：私信关键词或资料包名称（主人是做培训 / 资料 / 教育 / 咨询类引流的，优先"领资料"型钩子）

## 保存：一个选题 = 一份母稿 + 各平台版本
- **母稿** `30-Action 行动/工作成果/内容作品/母稿-<短标题>.md`：选题、核心观点、论证结构、用到的知识页；`platform: 母稿`。
- **平台版本** `30-Action 行动/工作成果/内容作品/<平台>-<短标题>.md`：`up` 指向母稿，`account` 指向账号档案。只写一个平台时也先建母稿，方便以后多发。

平台版本 frontmatter：

```markdown
---
up:
  - "[[母稿-<短标题>]]"
related:
  - "[[问题页]]"
created: YYYY-MM-DD
type: work
tags: [内容作品]
WIPstatus: simmering
platform: 小红书
account: "[[小红书]]"
published:
views:          # 发布后回填：播放 / 阅读
leads:          # 发布后回填：带来的私信 / 咨询数
sources: ["[[问题页]]", "[[观点页]]", "[[案例页]]"]
---
```

然后在用到的问题页 `used_in` 里追加 `"[[<内容作品文件名>]]"`。

## 红线
- 绝不出现真实客户名、公司名、联系方式；案例只用脱敏版本。
- 数据必须来自知识库（标出处）；没有出处的数字不写，或写成"据我观察"。
- 不编造主人没说过的个人经历。

## 收尾
在 `20-Wiki 知识/编译日志.md` 追加 `## [YYYY-MM-DD] content | 主题`，并告诉主人：写了几篇、建议先发哪篇、为什么。最后问一句：「定稿 / 发布后，要不要 `/loopback` 回流？」发布后可在作品里补 `published` 日期和数据（阅读、咨询数），回流时一起沉淀。
