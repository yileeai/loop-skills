# checkup：AI 落地诊断（给生意做体检）

## 输入
- `/checkup <客户名>`：在 `30-Action 行动/客户档案/` 找同名或别名匹配的档案。
- 找不到档案：先按 `90-System 系统/模板中心/客户档案模板.md` 的字段向主人确认 行业 / 规模 / 核心痛点 / 预算，新建档案后再继续。
- 如果主人问的是"这个生意模式可行吗"，在报告里加「可行性判断」一节（见下）。

## 收集信息（只读）
1. 客户档案 `30-Action 行动/客户档案/<客户>.md`
2. 相关咨询记录：`40-Review 复盘/咨询记录/` 中 `client` 指向该客户的笔记
3. 客户资料：`10-Raw 原料/04-客户咨询/` 中文件名含客户名的文件
4. 知识库：
   - `20-Wiki 知识/知识节点/概念方法/AI落地诊断框架.md`（诊断方法，**必读**）
   - 对应行业页 `20-Wiki 知识/知识节点/行业/<行业>.md`
   - 相关 AI 工具页、案例页、问题页（先查 `20-Wiki 知识/知识总目录.md`）

信息不足时，列出缺失项，问主人是"先按假设出初稿"还是"补齐再做"。

## 输出：诊断报告
写到 `30-Action 行动/工作成果/咨询交付/诊断-<客户名>-YYYY-MM-DD.md`：

```markdown
---
up:
  - "[[<客户名>]]"
related:
created: YYYY-MM-DD
type: work
tags: [咨询交付, 诊断报告]
WIPstatus: active
platform: 交付文档
client: "[[<客户名>]]"
last_updated: YYYY-MM-DD
---
```

## 收尾动作
1. 更新客户档案：`stage` 改为「方案」（若原来是线索 / 诊断中），在正文「交付物」下加链接 `[[诊断-<客户名>-YYYY-MM-DD]]`，更新 `last_updated`，并建议 `next_followup`（默认 3 天后，问主人确认）。
2. 在 `20-Wiki 知识/编译日志.md` 追加 `## [YYYY-MM-DD] checkup | <客户名>`。
3. 诊断中发现的**通用**规律（与具体客户无关），询问主人是否沉淀为 `知识节点/观点/` 或更新行业页（必须脱敏）。
4. 用 3 行告诉主人：最大机会、最大风险、建议的下一步沟通话术。
5. 最后问一句：「这份报告定稿后，要不要 `/loopback` 回流进知识库？」（定稿即回流）
