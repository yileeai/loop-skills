# replay：一次咨询，三份资产

一次咨询要产出三样东西：**咨询记录**（时间）、**更新的客户档案**（行动）、**脱敏的知识**（知识）。

## 输入
- `/replay <文件路径>`：通常在 `10-Raw 原料/04-客户咨询/`。
- `/replay` 后直接粘贴聊天记录或口述内容。
- 不知道是哪位客户时，先问主人。

## 第 1 步：咨询记录
在 `40-Review 复盘/咨询记录/YYYY-MM-DD <客户名> 咨询.md` 创建：

```markdown
---
up:
  - "[[<客户名>]]"
related:
created: YYYY-MM-DD
type: consult
client: "[[<客户名>]]"
date: YYYY-MM-DD
duration:
tags: [咨询记录]
sources: [10-Raw 原料/09-已归档/<转写文件>]
---

## 一句话总结

## 客户原话（痛点 / 目标 / 顾虑）
> 尽量保留原话，最能反映真实需求

## 我给出的建议

## 双方承诺
- [ ] 我方：…（截止 YYYY-MM-DD）
- [ ] 客户方：…

## 成交信号 & 风险信号

## 下次跟进
- 时间：YYYY-MM-DD
- 话术要点：…
```

## 第 2 步：更新客户档案
`30-Action 行动/客户档案/<客户名>.md`（不存在就用 `90-System 系统/模板中心/客户档案模板.md` 的字段新建）：
- 更新 `stage`、`next_followup`、`last_updated`（`budget` 有新信息就更新）
- 在正文「沟通时间线」末尾追加：`- YYYY-MM-DD [[YYYY-MM-DD <客户名> 咨询]] — 一句话`
- 在「痛点」「目标」下追加新信息，**不要删除主人原有的内容**

## 第 3 步：沉淀知识（必须脱敏）
先读 `20-Wiki 知识/主题地图/知识蓝图.md`，判断这次沟通对应矩阵的哪一行（行业）、哪一列（获客 / 转化 / 交付 / 提效），以及框架的哪一块。

从这次沟通里找可复用的东西，用「行业 + 规模 + 城市级别」代替客户真名。**原子化**：一页只讲一个问题 / 一个观点 / 一个案例。
- **问题** → `20-Wiki 知识/知识节点/问题/`：老板问的好问题。已存在就把 `asked_count` +1，并在正文追加新的提问场景。
- **案例** → `20-Wiki 知识/知识节点/案例/`：有结果数据的才算，`desensitized: true`。
- **观点** → `20-Wiki 知识/知识节点/观点/`：主人在沟通中说出的、有价值的判断（必须是主人说的，不能是你编的）。转写里主人的判断不够清楚时，**先追问主人一两句「你怎么看」**，用原话沉淀。涉及看项目的判断，挂到 [[生意判断五问]] 对应那一问下。
- **打法** → `20-Wiki 知识/知识节点/打法/打法-<行业>-<环节>.md`：这次沟通中验证或讨论过的「某行业在某环节怎么用 AI」。已存在就增量合并；在客户身上真正用过时 `verified_count` +1，达到 3 时提醒主人提炼 SOP。只是讨论、未试点的，写进行业页的「讨论中」，不建打法页。
- **行业** → 更新 `20-Wiki 知识/知识节点/行业/<行业>.md` 的痛点和场景。

每个新页面都要有 `up` 和 `## 关联连接`，并登记到 `20-Wiki 知识/知识总目录.md`。

## 第 4 步：归档与日志
- 若输入是 `10-Raw 原料/04-客户咨询/` 中的文件，原样移动到 `10-Raw 原料/09-已归档/`。
- 在 `20-Wiki 知识/编译日志.md` 追加：
  ```
  ## [YYYY-MM-DD] replay | <客户名>
  - **变更**: 新增 [[咨询记录]]; 更新 [[<客户名>]]; 沉淀 [[问题…]], [[观点…]]
  ```

## 收尾
3 行告诉主人：客户现在处于什么阶段、下一步做什么（含日期）、这次沉淀了哪几条可以做内容的素材，填进了蓝图的哪一格。
